# Foundry-managed model API

The deployment creates a portal-compatible model API that matches the API
Management integration generated by the Foundry portal. It is separate from the
OAuth model API used internally by the hosted agent.

## Authentication and routing

The model API requires an API Management Product subscription key:

- Header: `api-key`
- Query parameter alternative: `subscription-key`

The key authenticates the caller to API Management. API Management then uses its
managed identity to call the Foundry account with the
`https://ai.azure.com/` audience. The API key is not a Foundry model key.

## Retrieve the subscription key

Run these commands from the repository root after provisioning:

```powershell
$subscriptionId = (azd env get-value AZURE_SUBSCRIPTION_ID).Trim()
$resourceGroup = (azd env get-value AZURE_RESOURCE_GROUP).Trim()
$apimName = (azd env get-value APIM_NAME).Trim()
$subscriptionName = (azd env get-value APIM_FOUNDRY_SUBSCRIPTION_NAME).Trim()

$apiKey = az rest `
  --method post `
  --url "https://management.azure.com/subscriptions/$subscriptionId/resourceGroups/$resourceGroup/providers/Microsoft.ApiManagement/service/$apimName/subscriptions/$subscriptionName/listSecrets?api-version=2024-05-01" `
  --query primaryKey `
  --output tsv
```

## Call the model API

```powershell
$accountName = (azd env get-value AZURE_AI_ACCOUNT_NAME).Trim()
$projectName = (azd env get-value AZURE_AI_PROJECT_NAME).Trim()
$modelGateway = "https://$apimName.azure-api.net/$accountName/api/projects/$projectName/openai/v1/responses"
$body = @{
  model = 'agent-model'
  input = 'What is Azure API Management?'
  store = $false
} | ConvertTo-Json -Compress

$body | curl.exe --request POST $modelGateway `
  --header "api-key: $apiKey" `
  --header 'Content-Type: application/json' `
  --data-binary '@-'
```

A request without `api-key` or `subscription-key` returns HTTP `401`.

## Project limits and Foundry portal metadata

The API belongs to an APIM Product with a Product-scoped subscription. Bicep
renders `modelTokenLimit`, `modelTokenQuota`, and `modelTokenQuotaPeriod` into
the Product Policy. The same variables:

- appear as model-limit metadata in the Foundry portal; and
- are consumed by `foundry-project-model-key-auth-policy.xml` to enforce aggregate limits
  on the subscription-key API.

These project settings are not APIM named values. Update their Bicep values and
run `azd provision --no-prompt` to change them.

## OAuth hosted-agent API

The hosted agent uses a separate OAuth model API. That route:

- authenticates the hosted-agent Microsoft Entra identity;
- uses the APIM managed-identity backend;
- applies per-user token limits and model Content Safety on its POST operation;
- does not accept the Product subscription key; and
- does not apply the Product aggregate project-limit policy.

## Switch the hosted agent from OAuth to API-key authentication

By default, the hosted agent calls the OAuth model API through
`APIM_OAUTH_FOUNDRY_PROJECT_ENDPOINT`. Use the following procedure to make it
call the Product subscription-key API instead.

> [!IMPORTANT]
> The two APIs enforce different policies. After this change, model calls use
> the Product-level aggregate token limit and quota. They no longer use the
> OAuth API's hosted-agent identity restriction, per-user token limits, or model
> Content Safety operation policy.

### 1. Provision the subscription-key API

Provision the infrastructure before retrieving the key. Provisioning creates
the APIM Product and its Product-scoped subscription:

```powershell
$env:AZURE_DEV_USER_AGENT = 'microsoft_foundry_skill'
azd provision --no-prompt
```

### 2. Retrieve and store the APIM subscription key

Retrieve the Product subscription key as shown in
[Retrieve the subscription key](#retrieve-the-subscription-key), then store it
in the local azd environment:

```powershell
azd env set APIM_FOUNDRY_SUBSCRIPTION_KEY "$apiKey"
```

Do not commit or print this value. The `.azure` environment directory is
gitignored, but anyone who can inspect the deployed agent's environment may be
able to read the key. Rotate the APIM subscription key if it is exposed.

### 3. Configure the hosted agent

In `azure.yaml`, change the model endpoint and add the subscription key to the
hosted-agent environment:

```yaml
services:
    agent:
        environmentVariables:
            - name: AGENT_MODEL_DEPLOYMENT
              value: agent-model
            - name: AGENT_APIM_PROJECT_ENDPOINT
              value: ${APIM_FOUNDRY_PROJECT_ENDPOINT}
            - name: AGENT_APIM_SUBSCRIPTION_KEY
              value: ${APIM_FOUNDRY_SUBSCRIPTION_KEY}
```

`APIM_FOUNDRY_PROJECT_ENDPOINT` targets the Product subscription-key API.
Do not use `APIM_OAUTH_FOUNDRY_PROJECT_ENDPOINT` in this configuration.

### 4. Add the `api-key` header to model requests

Update `src/main.py` so `FoundryChatClient` sends the APIM subscription key:

```python
api_key = os.environ["AGENT_APIM_SUBSCRIPTION_KEY"].strip()
if not api_key:
    raise RuntimeError("AGENT_APIM_SUBSCRIPTION_KEY must not be empty.")

client = FoundryChatClient(
    project_endpoint=os.environ["AGENT_APIM_PROJECT_ENDPOINT"].strip(),
    model=os.environ["AGENT_MODEL_DEPLOYMENT"].strip(),
    credential=credential,
    default_headers={
        "api-key": api_key,
        "User-Agent": "apim-hosted-agent-v1",
    },
    middleware=[EndUserIdentityForwardingMiddleware()],
)
```

Keep `credential=credential`. The Foundry SDK requires a token credential to
construct its project client, even though APIM authenticates these model
requests with the `api-key` header. APIM uses its managed identity for the
backend Foundry request.

The end-user identity middleware can remain for compatibility with the agent
ingress route, but the subscription-key API does not use that identity for
per-user token enforcement.

### 5. Deploy and validate

Deploy a new hosted-agent version:

```powershell
$env:AZURE_DEV_USER_AGENT = 'microsoft_foundry_skill'
azd deploy --no-prompt
azd ai agent invoke agent 'Reply with exactly: key authentication works'
```

A successful response confirms that the hosted agent can call the model through
the subscription-key API. A missing or invalid key returns HTTP `401`; an
exhausted Product token limit or quota returns HTTP `429`.

### Roll back to OAuth

To restore the default architecture:

1. Set `AGENT_APIM_PROJECT_ENDPOINT` back to
   `${APIM_OAUTH_FOUNDRY_PROJECT_ENDPOINT}`.
2. Remove `AGENT_APIM_SUBSCRIPTION_KEY` from `azure.yaml`.
3. Remove `default_headers={"api-key": api_key}` and the key-loading code from
   `src/main.py`.
4. Deploy a new hosted-agent version with `azd deploy --no-prompt`.

See [APIM Policy Reference](APIM-POLICIES.md) for the complete policy map.
